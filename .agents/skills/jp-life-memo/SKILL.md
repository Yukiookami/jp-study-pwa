# 聊天中的生活摘录

适用于“加入生活摘录”“这个说法帮我收进日语手帖”等请求。课堂录像仍用 japanese-lesson-memo；单纯询问含义而未表示收录，不自动写入学习库。

## 固定流程

1. 在 jp-study-pwa 仓库工作，读 AGENTS、docs/data/LESSON_FORMAT.md 与 docs/data/DATA_RULES.md。确认输入中的日语、中文意图、场景和真实日期；普通文字可以直接处理。只有正确表达或关键语境无法确定时才补问，能独立完成的解释先完成。
2. 按已有来源写中文说明，分为“表达方式”和“单词”，含假名、适用场景、搭配及日中例句。用户提供的原话与补充例句分开；反推错误不是实际原话。生活内容不伪装成课堂或老师纠正。需要外部核对时优先可信日语词典等来源。
3. 在 lessons/YYYY-MM-DD_生活摘录/ 保存 memo.md + lesson.json，同日已有摘录则追加或修订；实际遇到日期未知时 lesson_date=null，created_date 使用整理日期，标题可用“生活摘录｜整理于 YYYY-MM-DD”。lesson.tags 必须含“生活摘录”，应用据此归类；不要占用第一课、第二课编号。没有实际材料时不创建空记录。
4. 使用现有 schema_version=1。新 ID 采用规定前缀 UUID；同一摘录修订保留已有 lesson/expression ID。单词按日语、读音和本义项查已有词条，真正同义项沿用 vocabulary ID，并在本条来源保留完整词条及例句；不因同形就合并不同义项。
5. origin 使用 assistant_supplement 表示整理补充；确定并有来源支持的用法标 source_supported，用户明确确认的原话可标 user_confirmed；目标表达本身不确定则 needs_review 并记 unresolved，不进入背诵。不把“用户确实听到了这句话”当作语法正确性的证明。原错误缺失时 original_japanese=null，不强行构造纠错卡。
6. 原子保存文件：在同目录临时文件中完成写入后替换正式文件，保持 Memo 与 JSON 对应。用 jp-lesson-validate 的只读脚本校验全部课程；必要时验证服务器公开 API 的条目。服务运行时由事件监听自动导入；服务未运行时说明内容已保存，可在数据库可用时执行已有导入命令；不要承诺服务端已经更新而没有核对结果。
7. 简短返回收录内容、归档日期、未确认项和实际同步状态。收藏、复习事件和进度不写入源文件；不自动提交或推送 Git。

可直接说：“加入生活摘录：今天同事说了……，场景是……，我想知道它怎么用。”场景可省略；不要求用户套模板或先编辑 JSON。
