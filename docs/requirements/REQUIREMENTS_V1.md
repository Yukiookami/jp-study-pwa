# V1 需求：个人日语学习 PWA

状态：第一版已实现，自动验收记录见 docs/development/VERIFICATION.md；手机真机验收待完成。本文把已确认方向与建议默认值区分开；后续用户调整以最新指示为准。

## 1. 目标与已确认约束

用户需要批量整理日语课堂内容，并在手机上方便阅读、背单词和练表达。正式课程统一分“表达方式”和“单词”，不显示时间戳；原说法、推荐说法、解释、搭配和例句都要保留。

已确认：Vue 3 + Vite，后端 Node.js，数据库 PostgreSQL；参考既有菜谱项目的工程习惯。Mac 运行服务，手机经已配置的 Tailscale 访问。仓库为 `Yukiookami/jp-study-pwa`，正式 `lessons/` 放在仓库内；处理材料和工具在 AI-output。

第一课作为验收数据：日期 2026-10-11，合并两段材料。目前含 52 项表达、106 个词条；以实际 JSON 为准。后续新增课程不需要修改页面代码。

## 2. 第一版默认范围

以下是供实施的默认方案，尚未经过真机验收：单人使用、不建设账号注册；课程浏览、词库、搜索、收藏、三类卡片、简单间隔复习、服务器持久化进度、已下载课程离线阅读和离线答题重连同步。复习规则见 DATA_RULES，后续可根据试用调整。

首屏以“今日复习”为主，导航包含“今日复习”“课程”“词库”；设置入口用于数据状态与备份操作。产品正式名称和视觉配色在界面设计阶段确定，工程名使用 jp-study-pwa。

## 3. 功能与验收

### R01 课程发现与导入

后端从配置的 `LESSONS_ROOT` 读取每课 `lesson.json`；启动时扫描，并提供页面上的“更新课程”操作。第一版不必上文件监听服务。

- 一课导入原子化；某课无效时显示课程名和可理解的错误，其他课仍可使用。
- 重复导入同一内容不创建重复课程、卡片或例句，也不重置进度。
- 同 ID 的内容修订更新显示，并保留记录；异常 ID 冲突阻止该课导入。
- `memo.md` 是阅读文件，不是替代 JSON 结构的解析来源。
- 源目录暂时缺失或文件删除不自动删除数据库课程与学习记录。

验收：首次导入第一课，显示实际全部条目；连续导入两次数量不变；修改一个解释后只更新内容；把新课程放入目录并更新后可见。

### R02 课程阅读

列表显示课程名称、日期、表达与词条数量。详情只有“表达方式”“单词”两个主要分区，支持展开解释和例句。

- 显示日语原文、中文说明、假名读音、词性与搭配。
- “原说法”和“反推错误示例”标签不同；反推示例不是用户实际原话。
- 课堂例句与补充例句有轻量标识。
- 待确认条目能查看，明确标识，默认不加入背诵。
- 长句、表格在手机可阅读，不以整页横向滚动作为常态。

验收：第一课所有条目可查看；「伝えば → 伝えれば」与“复习更方便”的反推示例正确区分。

### R03 词库、搜索与收藏

支持搜索日语、假名、中文释义和课程标题；可筛选单词／表达、课程、主题、收藏。

- 同一稳定词条 ID 出现在多课时词库合并，保留课程来源及各课例句。
- 不把不同义项或近义词强行合并。
- 收藏存于服务器，刷新或换浏览器后可恢复；离线第一版允许查看已有收藏，收藏修改要求在线。

验收：搜“质量”“しつ”都能找到「質」；收藏后刷新保留；按第一课筛选正确。

### R04 背诵卡片

三种卡型：单词卡（日语→读音、意思、搭配）；表达卡（中文意图→推荐日语和解释）；纠错卡（错误→正确形式与原因）。

- 先显示题面，点击后显示答案；翻面后才允许评分。
- 评分为“忘了”“有点印象”“记住了”。
- 无原错误的条目不强行生成纠错卡；反推错误单独标注。
- 原错误不进入推荐答案或正向单词卡。
- 可按课程开始学习，也可复习所有到期卡片。新卡每天默认上限 10 张，可在设置中调整；首次导入不自动把全部词条当作当天已学。

验收：三类卡片方向正确，翻面交互可用；答题不跳错卡、不重复计数。

### R05 复习计划与进度

记录卡片的阶段、上次评分、下次到期时间和答题历史。进度针对“条目 ID＋卡型”，同一词条不同方向可以独立复习。

- 服务端持久化；内容更新不清空进度。
- 今日页面显示当前到期数、新卡余量、本日完成数。
- 日界线按 Asia/Tokyo，数据库时间存 UTC。
- 默认调度规则和事件去重见 DATA_RULES，代码不得另写一套不一致逻辑。

验收：评分产生正确到期时间；刷新或重启 API 后仍保留；重复请求不增加第二次答题记录。

### R06 PWA 与离线

支持 Manifest、安装图标、独立窗口与静态资源缓存。用户在线访问／下载过的课程可离线阅读和背诵；首次打开一个从未缓存的课程需要联网。

- 离线评分存 IndexedDB 待同步队列，明确显示未同步数量。
- 网络恢复后同步；重复提交事件不重复计数，失败事件保留可重试。
- 新课程更新、在线收藏修改、备份操作要求可连接 Mac 服务。
- 离线阶段显示的调度与进度为暂定；服务器回执后刷新权威状态。
- Service Worker 更新提示不能导致待同步记录丢失。

验收：通过 HTTPS 从手机访问，能加到主屏幕；断网后打开已缓存课程并答题；重连后数据只入库一次。

### R07 Mac 运行与 Tailscale 访问

生产页面与 `/api` 使用同一 HTTPS 入口。数据库只允许宿主机连接，不向手机开放数据库端口。数据库容器与菜谱项目使用不同服务配置、端口和数据卷。

Tailscale 已由用户配置；HTTPS 入口具体方案在设备联调时核对，不凭空假定已完成。Mac 休眠或停机时不能提供新内容与同步，已缓存内容仍可用。

验收：手机连 Tailscale 后能读取第一课、答题保存；HTTPS 安全上下文成立；服务器重启后课程与进度保留。

### R08 备份与恢复

提供文档化的 PostgreSQL 备份和恢复操作，同时备份 `lessons/`。第一版不要求在网页恢复数据库，也不承诺定时自动备份。

验收：在隔离测试库恢复备份，课程、收藏和复习历史完整；不能在验收中直接覆盖正在使用的数据。

## 4. 第一版不做

视频上传与应用内语音识别、在线 AI 生成、多用户注册登录、推送提醒、语音评分、原生 App 打包、社交排名、复杂统计、公开互联网部署。日语发音播放以后单独评估；本版不声称有音频资源。

## 5. 需在对应阶段确定的事项

- 手机系统与浏览器：真机 PWA 验收前确认。
- 产品名称、配色和卡片视觉：页面设计时确认。
- HTTPS 入口与开机启动方式：Mac/Tailscale 联调时确定。
- 每日新卡数和复习间隔：初版按默认值实现，试用后调整。

这些不阻塞基础工程与数据导入实施。
